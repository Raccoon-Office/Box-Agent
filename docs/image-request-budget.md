# 图片请求大小

OpenAI-compatible provider 在发送前检查完整 UTF-8 JSON，包括文字、工具定义和本次 Base64 图片。native 主模型请求与 proxy 视觉请求共用此检查；它独立于上下文 token 预算。

- 内置 `xiaohuanxiong.com` 及其子域默认上限 10,000,000 字节，预留 5%，实际发送预算 9,500,000 字节。其他地址，包括自部署 208，默认不设此上限。判断依据是地址，不是模型名。
- YAML 顶层 `max_request_body_bytes` 配置主模型；`lite_llm.max_request_body_bytes` 单独配置 Lite 端点。模型 profile 使用 `maxRequestBodyBytes`。值为正整数；省略或 `null` 使用端点默认值。例如确认服务端支持32MB后可配置 `max_request_body_bytes: 32000000`。不同端点不继承对方的限制；ACP现有Lite复用主客户端的路由保持不变。
- 原有读取限制保留：每次最多6张、单张20MiB、合计60MiB、长边归一化1568。这些是文件读取限制，不能代替完整请求字节检查。

超限时才额外处理发送副本：先尝试同尺寸 JPEG quality90、4:4:4，实际更小才采用；有透明内容的PNG不转JPEG。多图仍放不下，明确返回 `REQUEST_BODY_TOO_LARGE`，由模型改为较小批次。单图仍超限，才有限缩放，长边不低于1024；仍超限需读取相关高清局部或减少文字，不能无限降低质量。原图与历史消息不修改；编码参数不等于文字已通过可读性检查。

PPT Skill要求每次模型响应只调用一次 `inspect_images`，每批最多4张；得到视觉结论、记录已检查及待检查页面后，再看下一批。4张放不下就改2张或1张；局部检查不能冒称整页验收。此规则不改变通用工具6张上限；若模型同轮调用两次native，两批会汇入下一次请求，由最终总字节检查阻止超限。

只有本地确认未发送的native图片请求才自动返回模型重试，保留未检查的路径和指令，每轮最多3次，并受原有步数限制。proxy通过工具错误返回相同指导。远端413不原样重试。`llm.request_payload`记录请求原始及处理后字节数、图片数量、转换尺寸，不记录Base64。
