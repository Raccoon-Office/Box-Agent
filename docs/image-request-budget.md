# 图片请求体大小控制

HTTP 请求体字节限制与模型上下文 token 限制分别检查。OpenAI-compatible provider 在发送前计算完整 UTF-8 JSON，包括历史文字、工具定义和所有 Base64 图片。native 主模型请求和 proxy 视觉请求共用这一步。

## 端点配置

内置 `xiaohuanxiong.com` 及其子域名网关默认上限为 **10,000,000 字节**，发送预算预留 5%，即 **9,500,000 字节**。判断依据是 API 地址，不是 `sn` 模型名。其他地址（包括自部署 208）默认不施加这一上限。

主模型在已有 YAML 配置的**顶层**添加正整数 `max_request_body_bytes`；Lite 模型则在 `lite_llm` 下配置同名字段，明确声明各自端点上限。例如，只有主模型服务端确认允许 32,000,000 字节时，才配置：

```yaml
max_request_body_bytes: 32000000
```

省略或 `null` 使用端点默认值；不接受 0、负数或字符串。独立模型 profile 使用 `maxRequestBodyBytes`，不继承其他地址的限制。同一端点的模型切换保留本端点配置。ACP 现有 Lite 路由仍复用主客户端，此配置不改变路由。

## 超限处理顺序

1. 保留现有图片读取资源限制及长边 1568 的归一化。完整请求未超过发送预算时，不额外转码或缩放。
2. 超限时按图片体积从大到小尝试同尺寸 JPEG，质量 90、4:4:4；只有实际更小才替换发送副本。保留有意义的透明通道，不修改原文件和会话消息。
3. 多张图仍装不下，返回 `REQUEST_BODY_TOO_LARGE`，由 agent 显式重试较小批次。provider 不拆分 HTTP 请求，也不悄悄丢图。
4. 单张仍超限，才有限缩放，长边不低于 1024，不放大原本较小的图片，JPEG 质量保持 90。仍装不下就请求局部高清图或减少非图片内容；不能继续降低质量。编码参数不能证明文字可辨认，视觉检查仍需判断实际细节。

CMYK 和 16 位/浮点灰度等模式不直接转 JPEG，避免偏色或亮度截断；单张缩放也只尝试保留像素模式的编码，不能安全处理时保留原数据并返回明确失败。普通灰度转 JPEG 仍保持灰度色彩空间。

native 本地超限时，主循环移除未发送的临时图片，保留其路径、检查指令及“尚未检查”说明，让模型重新调用工具。每轮最多恢复 3 次，并受原有步数限制。proxy 通过普通工具失败结果返回同样的明确指导。远端 HTTP 413 单独分类，不原样重试。

PPT Skill 每次模型响应最多调用一次 `inspect_images`，每批最多 4 张；收到实际结果并记录已检查页面、发现的问题和待检查列表后，再在下一次模型响应中继续。4 张仍超限时改为 2 张或 1 张。总览和逐页细查都保留，读取失败不能计入已检查覆盖率。共享工具原有每次最多 6 张的通用限制不变。

4 张属于 Skill 指令约束。工具单次传 8 张会被原有 6 张上限拒绝；若模型违反指令，在同一响应发出多个 native 调用，图片仍会汇入下一次主模型请求，由累计 token 和请求字节限制检查，provider 不额外施加 4 张硬上限。单张需要局部高清检查时必须记录已覆盖/待检查区域，不能把局部检查等同整页验收。

`llm.request_payload` trace 记录原始/准备后字节数、发送预算、图片数量和转换尺寸等元数据，不记录原始图片或 Base64。
