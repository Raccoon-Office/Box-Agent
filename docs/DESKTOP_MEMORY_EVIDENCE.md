# Desktop Experience evidence boundaries

Evidence starts at the exact current user message in the canonical Session Log. When that message has not yet been persisted, collection starts at the current end of the log; it never locates a prior turn by matching text alone. If the current message cannot be bound to the active log surface, evidence collection fails closed while ordinary QA remains independent.

Memory tools, including ordinary and Experience searches, are recall operations, not fresh execution evidence. Their call/result pairs are omitted from new evidence. The desktop Host rejects any Fact that cites a memory-tool call or result, even alongside other evidence. Each cited tool result must have a matching, fully readable, named non-memory call, and an execution-result Fact must also cite a successful result. Before a new cloud-write stage, the Host checks previously frozen plans too and freezes unsafe plans with their original evidence intact. An already-sent unknown stage can only be reconciled with its original request and key; unsafe subsequent stages remain frozen. The evidence format and pipeline version remain unchanged.

Any redaction or omitted attachment makes the affected view an excerpt, even when it fits the byte limit; its hash still identifies the filtered view. The Host also rejects legacy tool evidence containing redaction or attachment-omission markers, including old views incorrectly marked full. This conservative check can reject literal marker text. Private desktop diagnostic scopes suppress MCP result adapter exception traces that may contain tool payloads.
