## 修改方案

- 固定边界：ACP 线协议、CLI 展示、第三方模型配置及桌面独立运行不变；不增加网页、UI、安装或重启步骤。
- 保持行为：验证 CLI、ACP、SDK 使用同一 AgentService/AgentRunHandle 交付机制，补充公共入口集成测试。
- 功能变化：仅在回归发现缺陷时修复容量、取消或权限交付错误；内部交付失败进入既有错误响应，不能映射为正常结束。具体差异提交前记录。
- 验收：慢 ACP 发送、权限反向请求、等待时取消、交付失败；小容量稳定积压；相关运行、Core、Session、Tool Engine、ACP、架构测试；按 preflight 范围执行锁定依赖、编译、完整测试和构建。
- 环境：通过现有 BOX_AGENT_HOME 将测试状态隔离到 workspace；UV_CACHE_DIR 使用 workspace。Windows 平台基线失败和环境阻塞分开记录，不修改锁文件绕过检查。
- 兼容与回退：继承 T2–T5 已记录的接口增量和消费模式变化；本项单独回退仅撤销适配修复和集成验证，不回退前序设计。

## 实施与验证

### 实际修改和方案细化

- ACP 原取消只更新 Session 标志；Session 现在同时唤醒当前 handle 的交付/控制等待。自定义 command_sink 收到取消前同样唤醒共享通道。
- 普通宿主权限 negotiator 经 AgentService 包装为可取消等待，ACP 反向请求和权限协议不变。取消清理等待任务，批准与拒绝均保留现有结果。
- ACP 发送超时从事件通用捕获中重新抛出，使用既有请求异常路径，不伪造正常结束。
- SDK `run()` 改为真正调用仅结果模式。执行/交付失败通过 RunResult 返回；需要异常式消费的调用方使用流式接口。权限回调返回前未回复即拒绝。
- 权限事件的发布失败保留为运行失败，不能被工具层捕获后改写成正常结束。
- 终止事件成功入队后才进入结果聚合，避免 Done 尚在等容量时过早拒绝取消；错误结果仍独立于队列完成。
- 入口回归使用真实 ACP newSession/prompt/cancel 与共享 Service，替代 Kernel 仅提供受控事件或权限请求。CLI 既有公共入口测试增加临时用户目录隔离。
- 原 Core 的直接/委派预算分离测试改用接入账本的可信替代工具，保留父直接额度不被子调用消耗的验证。
- 并发心跳回归曾在 Windows 的 12ms sleep 竞争下间歇失败，改为事件同步等到心跳再放行工具；没有修改调度产品行为。
- 增加首次消费者登记竞争、SDK 仅结果权限、等待终止事件时取消、重复积压 tracemalloc 检查（热身后 400 轮，保留内存增长 <256 KiB）。这不承诺整个任务固定内存。
