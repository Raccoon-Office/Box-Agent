# T5：委派共享硬预算

## 修改方案

- 固定边界：直接工具预算、子任务自身额度、能力/权限/写范围、路由和默认值不变；不改变模型 schema。
- 功能变化：父 Engine 为委派额度创建共享账本，内置 sub_agent 通过调用上下文绑定祖先账本。每次子工具进入共享调用入口前，同步检查并扣减所有祖先额度，无 await 间隙。
- 实现策略：只在真正调用前预留，排队/Hook 拒绝/批内去重无需预占；参数非法不消费，明确权限请求释放预留，已执行的成功、失败、取消保留扣费。同一调用的权限重试复用 charge。
- 嵌套：子 Engine 继承祖先账本，并为自己的委派限制增加账本；子任务返回计数仅作统计，不再决定已接入账本的硬限额。
- 替代实现：配置硬上限时，未声明并实现 invocation-context 账本协作契约的 sub_agent 拒绝执行。声明者属于可信插件，必须接受契约测试。
- 范围：单事件循环内原子额度，不提供跨进程额度服务。ContextVar 仅在子任务执行作用域绑定，退出必定 reset；实例不存储某个并发调用的账本。
- 验收：并行、嵌套、取消/异常、权限重试、非法参数、替代实现和未配置限制；覆盖真实子 Agent 调用入口。
- 回退：整体回退提交恢复完成后累计的旧行为；无需状态迁移。
