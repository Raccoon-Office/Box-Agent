# T3：流式与仅结果消费

## 修改方案

- 固定边界：单流式消费者、后台启动、结果聚合及 ACP 权限反向请求不变。
- 功能变化：第一次开始 events 迭代或等待 result 决定消费模式。result 先行时内部排空，后续 events 明确报错；重复 result 共享 Future，取消等待者不取消执行。
- 关闭：使用独立 closed 状态唤醒消费者，保留先读完已有事件再结束的顺序。
- 权限：仅结果模式使用 PermissionBroker 原有 on_request 回调。回调必须在返回前提交 response（可 await 用户交互）；返回后仍无响应视为明确拒绝。切换时已有 pending 请求也按此处理。ACP 自有协商器不变。
- 验收：消费竞争、大量通知、多个 result 等待者、无消费者关闭、权限允许/拒绝及切换时 pending 请求。
- 回退：回退本提交。文档明确 result 先行后不能补读事件，调用方应先订阅 events。
