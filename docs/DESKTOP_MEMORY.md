# Desktop memory launch and recovery

## MemSense 2.2.3.8 Experience protocol (2026-11-03)

The producer requires Host pipeline `desktop-experience-v2`. Evidence view/version and its nine source-reference fields remain unchanged. Fact proposals use `entities: string[]`; Observation proposals additionally require an explicit `memory_type` (`user_preference`, `round_experience`, or `operation_experience`), `scenario`, `content`, and nonempty `rationale`. Search is by scenario and type; Host hydrates current records and validates supporting Facts before use. There is no remote Entity registration, etag, or Entity save stage. Host-provided names are applicability labels, not authorization or evidence that a Skill was used; version-qualified labels preserve the existing Skill applicability boundary.

The Host persists the original Fact/Observation plan, idempotency keys and expected revisions. Old-pipeline unsent work retires; sent unknown work remains frozen with its original payload instead of being translated/replayed under a new key. Each producer job request declares its pipeline version; Host rejects missing or incompatible versions before claiming or changing work, and the producer also verifies Host responses. Existing evidence provenance, identity, revocation, queue limits, complete-input budgets and payload privacy remain in force. A new frozen runtime must be built, installed and restarted before this behavior is live.

The desktop host selects the package's fixed cloud/local mode. For a cloud process it supplies `BOX_AGENT_MEMORY_MODE=desktop`, `BOX_AGENT_MEMORY_BOOTSTRAP_FILE` and `BOX_AGENT_MEMORY_IDENTITY_EPOCH`. These are private launch metadata, not model/tool parameters. Shared YAML may keep `enable_memory: false` for older runtime compatibility.

The shared config loader applies `desktop_memory.launch.desktop_launch_agent` before constructing a memory manager. A valid native grant enables the desktop backend and disables local extraction; it does not read or wait for the bootstrap file. Invalid native metadata disables memory without falling back to local memory. The capability consumes those environment variables and keeps a process-private copy for reloads, so shells, MCP servers and tools do not inherit the bootstrap location.

ACP initialize advertises `_meta.desktop_memory` with `protocol_version: 2`, `backend: desktop`, `enabled`, and `attempt_log_v1: true`. Hosts must validate the current process and lease as well as this capability before publishing the cloud route. The response contains no launch path, epoch or credentials.

Before context loading, the desktop runtime appends and flushes an ignorable `memory/desktop-attempt` extension in the existing canonical Session Log. It stores only a hashed turn key and original timestamp. Recovered attempts send `require_existing: true`: the host restores an existing binding, or records unavailable if the first attempt never reached it. This prevents bootstrap delays or migration completion from retroactively making an old turn learnable. Failure to persist the attempt skips memory for that turn; it never sends an unprotected context. Temporary programmatic sessions without a Session Log keep only an in-process attempt set and have no cross-process recovery guarantee.

## Evidence and background Experience production

The runtime can hand off bounded, redacted views of the current turn's canonical Session Log with its QA through the native control capability. Missing evidence permits ordinary QA but cannot produce an evidence-backed Experience. A `durable_unknown` receipt is not confirmation that QA was saved; the host retains the original input for reconciliation.

QA user/assistant text and evidence use the same credential filter. Recognized credential assignments (including Chinese labels, fullwidth colons, prefixed environment names, escaped JSON and nested fields), password/user CLI arguments, authentication/cookie headers, private keys, known token formats and password-bearing URLs cause the entire suspect string or field value to be omitted. URL userinfo is scanned without overlapping username/password quantifiers, so colon-heavy input takes linear time. Ordinary `key`, `cache_key`, `primary_key`, `total_token` fields and prose mentioning "Bearer token" are retained. Hashes describe the filtered view. This does not identify arbitrary unlabeled secrets; hosts must still treat handoff data as private. Canonical Session Log and foreground model input stay intact.

If either QA side is replaced in full, handoff returns the local-only `skipped_redacted` state without sending QA or evidence to the host. The runtime closes the turn, records only that state and does not trigger Experience production for this handoff. Tool evidence still filters individual suspect values before hashing; safe QA can carry those filtered views. Previously pending host jobs may still reconcile independently.

Filtering applies to new handoffs and does not scrub previously accepted host material. If an existing event has a different frozen payload, the host must retain its original reconciliation contract; do not replace it or mint a new event to bypass an idempotency conflict.

User evidence must exactly match the original text or a verified framework wrapper. For first or changed connector snapshots, both cursor selection and capture reconstruct the expected content from the event's separate trusted `host_connector_status` field using the shared connector formatter. They never infer host metadata from user-authored tags or use substring matching. This also covers unavailable snapshots, trailing whitespace, active goals, and image messages persisted before memory refresh. Only the original user text enters the evidence view; removing a host/framework wrapper marks it as `coverage: excerpt` with `excerpt_limit: 4096`, which the existing host evidence contract accepts.

For eligible online cloud sessions, `ExperienceRuntime` uses the control-only `experience/job` operation to claim work, obtain a host-frozen model input, submit a proposal and advance persistence. Model generation runs in the background without tools or changes to the main conversation history. It has a 30-second timeout and a capped output budget. The host validates evidence and proposals, owns durable leases and idempotency, and saves Fact and Observation records. Box-Agent never writes those records directly to an external database. An uncertain persistence result stops advancement for that activation; later activations resume the host-owned state rather than inventing a replacement plan. An empty supported proposal may finish with no candidate.

Hosts must implement the named proxy operations and enforce identity, session, read-visibility and write-protection boundaries. Backend deployment, authorization policy and product rollout remain the host's responsibility. The default local backend does not require this service.

## Diagnostic privacy and revocation

Private desktop payloads are omitted at the shared trace writer, including ACP input and error events that write directly. Model input and the canonical Session Log retain their normal semantics. After authentication, identity or memory-disable rejection, final input projection removes the owned preload block before checking whether the request fits its budget. It does not rewrite durable history. Utility sessions keep memory tools, extraction and persistence disabled; existing local host metadata used for UI guidance remains compatible, while desktop utility sessions retain no usable backend.

Injection diagnostics contain IDs and character counts, never text. Unknown model aliases retain the conservative UTF-8 byte bound; preload reduction and full-read rejection emit payload-free budget diagnostics. A late `TURN_REVOKED` affects only the matching binding, while identity/session revocation remains global. Failed visibility control requests are logged without raw errors. Full handoff queues skip QA explicitly and use a separate bounded close allowance; if that allowance is also full, a diagnostic records the unconfirmed close and host idle expiry remains the fallback. Background scans back off between pages/stages, continue remaining pages in bounded delayed batches, and stop on unknown states. YAML alone cannot enable desktop memory without native launch metadata.

The private diagnostic scope also suppresses raw core-loop and Hook diagnostics, including suspected-truncation response tails and Hook exception messages that may contain model or tool payloads. Ordinary diagnostics outside that async scope retain their configured behavior.

Bash diagnostics can contain command text and are suppressed in the private scope as well. A Host `MEMORY_SESSION_RETIRED` rejection clears the session's preload and read qualifications. The Host also uses that code when an Experience job's source session is retired; since the response does not distinguish the two cases, this rejection conservatively clears memory for the current turn. After a full batch of three Experience claims, the producer schedules a bounded delayed scan even when every claim returned a job; unknown outcomes still stop advancement.

## Verification boundary

Focused checks: `uv run pytest tests/test_desktop_memory_launch.py tests/test_desktop_memory_attempts.py tests/test_desktop_memory_backend.py tests/test_desktop_memory_transport.py tests/test_desktop_memory_visibility.py tests/test_desktop_memory_evidence.py tests/test_desktop_memory_experience.py tests/test_desktop_memory_windows_files.py tests/test_cli_config.py -q`.

POSIX bootstrap checks cover ownership, permissions and links; Windows uses handle-bound private-ACL checks. Portable Win32 test doubles and conditionally skipped native tests do not establish Windows machine acceptance. Source tests do not establish that a packaged desktop runtime was built, installed, restarted, or used by a fresh live task, or that an external host/backend deployment passed end-to-end acceptance.
