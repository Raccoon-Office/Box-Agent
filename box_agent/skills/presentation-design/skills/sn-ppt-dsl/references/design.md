# 设计与素材

保留 SN 大纲和素材来源记录。先定整体视觉方向、字阶、颜色、页边距和图片处理方式，再逐页自由布局。允许坐标构图，不限制为固定版式模板。

从技能根目录下的 `vendor/doubao/references/style/` 选择一个主场景：

| 用途 | 文件 |
|---|---|
| 分析决策 | `strategy-and-analysis.md` |
| 商业提案 | `business-pitch.md` |
| 管理汇报 | `business-review.md` |
| 学术研究 | `academic-research.md` |
| 教育培训 | `learning-and-training.md` |
| 技术工程 | `technical-presentation.md` |
| 品牌创意 | `brand-storytelling.md` |
| 其他场景 | `fallback.md` |

这些是移植的设计参考。用户品牌和效果偏好优先；其中的云端操作、图表全集和字体可用性不能直接当成本地能力。执行命令和支持范围以当前技能为准。


## 标题、正文层级与阅读顺序

首次写 XML 前，在已有 task_pack.json 的 state.design 中记录本册标题、正文、辅助说明的字号/字重/颜色及同类页面的标题位置，作为跨页基线，不另建大纲。现有字号建议是起点；按真实内容和画幅选择，封面、引语或关键数字可例外，并说明原因。

用成品字号排大纲里的短标题，正文页以单行为先。需要额外解释时，把信息放回对应数据或画面旁；不要在 XML 把短标题重新扩写成“栏目名＋判断＋数据”的长句。用户指定的完整标题或专名较长时，允许自然换行。标题与正文通过字号、字重、留白或位置区分，同级信息使用一致处理。

层级不清时，优先调整分组、间距、对齐和强调的数量，再调整字号与文本框；不要靠缩小正文、删去依据或把必要信息移出画面掩盖问题。图表、对比与流程按内容关系建立阅读路径，不统一强制左上到右下，也不为通过检查把所有页套成同一版式。

## 图片用途与来源


### 从理解任务选择视觉表达

逐页实现大纲的“理解难点→预期可见特征”，再决定素材与构图。先从用户附件和已有原图寻找能展示该特征的内容；真实界面、工艺或对象不能用仅同主题的图片冒充。流程或关系可以用原生形状画清：并行任务用汇聚/分区，异常用带触发条件的支线，箭头不能凭版面方便制造固定顺序或因果。精确数据使用保留分母、时间和单位的图表；只有地图轮廓而无相关区域信息时，不称为区域分析图。

选图后先实际查看，再检查页面要求的动作、部位或差异在当前裁切下是否可见。若不可见，换图、改裁切或换为合适的原生示意；没有合格来源则保留缺口，不用无关图片凑数。生成概念场景只表达构想，不模拟真实事实或已交付产品。多张照片拼贴也应明确视线落点，避免让关键对象退成很小的装饰。

主图可以让观众认出对象、看见差异，也可以为开场或转折建立现场感。先排主体，再排标题和证据：环境画面可铺满留白区，细节图可放大并配短注，原文对照可按同一尺度并列。让主体在投影距离仍看得清，文字避开脸、关键部位和图中标注。相邻页按内容换景别、占幅或构图，避免连续把图缩成同样大小的半页配件。原生图表继续承担比较和趋势。


按**图片承担的任务**选择素材，不按主题词或文件名套规则。先检查用户提供的图片是否合适；没有合适图片时按下表执行：

| 页面需要什么 | 选用来源 | 检查重点 |
|---|---|---|
| 可核对的真实事物、人物、产品、地点、实验现象或教材要求辨认的细节 | 搜图，优先一手或可核对的原图 | 核对页面描述、图片内容、来源和使用许可；不把生成图称为实拍或事实证据 |
| 氛围、故事、抽象概念或不承担事实说明的插画 | 生图，也可使用已获许可的现成插画 | 保持全册风格一致，不让模型画字；检查生成图是否出现误导性细节 |
| 图标、箭头、表格、流程、精确结构和已知数据图 | XML 原生形状/图表或 SVG | 保留关键文字为原生文本，保证结构位置与数据准确 |

在已有素材步骤集中处理选中的画面：优先复用附件或原文图，按图号与图注裁出有意义的区域。缺少实物或记录性画面时搜可核实的原图；需要场景氛围又没有合适原图时，可生图并标作示意。不要用生成图冒充研究结果或真实产品。素材处理完成后把所选文件实际引用到该页 XML。全册预览时顺手确认所选画面在成品中出现、主体清楚，且图注与图相符。

素材可跨页复用，但检查每次引用是否承担明确作用。重复整张氛围图会削弱页面节奏；适合时使用有意义的局部近景、另一观察角度或对应证据图，不为增加变化而强求每页生图。素材到位后逐页核对大纲要求的特征是否看清，结论不能由程序的“图片存在”检查替代。

搜图调用宿主能力或同级 `sn-ppt-design-tools/scripts/image_search.py`，从结果页核对来源及许可后再用 `fetch_image.py` 保存到当前任务 `assets/`。生图调用宿主能力或 `sn-ppt-design-tools/scripts/image_generate.py`，提示词放在任务 `assets/`；使用当前已配置的模型，无需新接口。按照 [能力选择规则](../../sn-ppt-design-tools/references/capability-policy.md) 处理失败，不静默把一种图片用途换成另一种。

`assets/sources.json` 是图片来源清单，不是第二套页面格式。每张 XML 引用的图片登记一条，`file` 使用 `assets/` 下的相对文件名：

```json
[
  {
    "file": "forest-at-dawn.png",
    "role": "scene_illustration",
    "origin": "image_generation",
    "model": "实际使用的模型名",
    "prompt_file": "assets/forest-at-dawn.prompt.txt",
    "purpose": "封面气氛"
  },
  {
    "file": "specimen.jpg",
    "role": "fact_photo",
    "origin": "web_search",
    "source_url": "https://example.org/original-image-page",
    "license": "实际核对的许可",
    "author": "实际署名",
    "purpose": "辨认真实形态"
  }
]
```

`role` 使用 `fact_photo`、`scene_illustration`、`diagram`、`icon`；`origin` 使用 `user_provided`、`web_search`、`image_generation`、`programmatic_vector`。真实照片只接受用户图片或搜图；氛围插画可来自用户、搜图或生图；程序绘制只用于结构示意和图标。确实没有合格图片时重新布局并明确说明缺口，不能把程序画的场景图记成已生图。来源页应清除带签名、鉴权或追踪参数的 URL；记录许可与署名要求，不记录密钥。图片文字、标题和教学标签放到 XML 原生对象。

图标先用本地索引搜索，避免猜名称：

```bash
python "<SKILL_ROOT>/vendor/doubao/scripts/iconpark_tool.py" search --query "趋势"
```

复杂图表可以使用已移植的 SVG 工具；先查看该图的参数，使用已知数据，并匹配整套配色和字体：

```bash
python "<SKILL_ROOT>/vendor/doubao/scripts/gen_svg_charts.py" --help
```

需要 Python 函数接口时，在 Python 中将 `SKILL_ROOT/vendor/doubao/scripts` 加入 `sys.path`，再导入 `gen_svg_charts` 并调用 `chart_help()`。SVG 保留为独立文件或内嵌于 `<embed>`；复杂图中的文字导出后属于图片。要求可编辑时优先使用原生 `<chart>`、形状和文本。

## 素材与成品检查补充

- 使用支持 `watermark` 参数的 SenseNova 生图服务制作无标识氛围素材时，显式追加 `--no-watermark`，并实际看图确认；提示词里的“无水印”不能替代请求参数。
- 从产品手册裁取证据截图时，先核实PDF页幅和元素边界；不要按未经检查的相对坐标裁剪。保留功能标题与完整关键界面，无法避免截断时改用完整原页并标注仅作功能出处，不把截图示例数字当客户实绩。
- 长条总览图只用于检查全册节奏；逐页阅读使用 `preview/manifest.json` 指向的分批审阅图，风险页使用原尺寸 PNG。页码已放在图片外，不再手工拼图或覆盖成品。看图后用 `dsl.py review` 记录页码，细节流程见 [成品验收](qa.md)。
- 用户旧模板可能含越界占位对象、隐藏页或裁切文字，导致严格成品预览入口拒绝。只为理解模板风格时，可将原模板单独用LibreOffice导出PDF并检查真实页面，记录旧模板问题、不改原件；新生成成品仍必须通过完整XML检查及正式preview验收。
- 演讲者备注应写可直接讲述的内容、来源与口径，不直接粘贴含版式指令和工作流文字的大纲。将长名单及证据边界移到备注，可保持管理汇报页面疏朗。
- 字阶或其他视觉对象使用阶梯布局时，将总说明文本限制在阶梯外的空白区域；跨越最高阶梯的文本框即使大部分文字未重叠，也容易产生真实遮挡或背景容器判定错误。

可参考 Kimi 的主题一致性、视觉层次和页面节奏，但不引入 PPTD；效果应来自具体设计决策，不通过增加第二种源格式实现。
